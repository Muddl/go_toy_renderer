# Specification: Live Performance Debug Overlay

**Track ID:** perf-debug-overlay_20260301
**Type:** Feature
**Created:** 2026-03-01
**Status:** Draft

## Summary

Add a toggleable live performance debug overlay rendered directly into the
renderer-rt window using a pure-Go bitmap font. F3 cycles through three
granularity levels (off → FPS → FPS+timings → per-system breakdown → off).
No new CGO dependency is introduced.

## Context

renderer-rt currently has no runtime visibility into performance. As the GPU
pipeline grows (Phases 13–16), regressions will be increasingly difficult to
spot without in-process tooling. The overlay is a developer-facing diagnostic
aid. Because the CPU backend owns a pkg/framebuffer pixel buffer and the GPU
backend uses wgpu, both code paths need a rendering strategy:

  CPU backend — composite text pixels directly into the CPU framebuffer before
  the GLFW/OpenGL blit (trivial, no extra pipeline).

  GPU backend — write text into a CPU-side RGBA byte slice, upload it as a
  wgpu Texture each frame, and composite with a second render pass (alpha
  blend, no depth write) after the main geometry pass.

Both strategies share the same pkg/overlay package, which provides pure-Go
metric types, a rolling FPS sampler, and a bitmap font rasterizer.

## User Story

As a developer, I want real-time GPU/CPU metrics visible inside the render
window so I can catch performance regressions immediately during manual
testing.

## Acceptance Criteria

- [ ] F3 key cycles: 0 (off) → 1 → 2 → 3 → 0 (wraps around)
- [ ] Level 1: rolling-average FPS (1 s window) shown top-left of window
- [ ] Level 2: FPS + frame time (ms) + total CPU frame time
- [ ] Level 3: all Level 2 + per-phase CPU timings (geometry upload, render
      pass encode, GPU submit/present) + backend name + mesh vertex/triangle
      count
- [ ] Overlay is rendered in-window (not window title bar)
- [ ] Text is legible at 1280×720 (≥6 px per character cell)
- [ ] CPU and GPU backends both display the overlay within their render window
- [ ] No new CGO dependency — bitmap font and text layout are pure Go
- [ ] Overlay at level 0 adds ≤0.1 ms overhead per frame
- [ ] Headless build compiles without overlay rendering (no-op stubs)
- [ ] All tests pass; CI green

## Dependencies

- Phase 9 (GLFW window + keyboard input via glfw.KeyF3)
- Phase 10 (pkg/renderer Renderer interface — both backends)
- Phase 11/12 (GPU backend for per-phase timing measurement points)
- pkg/framebuffer (CPU backend compositing)

## Out of Scope

- Persistent logging / file output
- Configurable key bindings (F3 is hard-coded)
- On-screen graphs / sparklines
- True GPU timestamp queries (wgpu timestamp feature)
- ImGui or any third-party UI library
- GPU-side font texture atlas (bitmap is CPU-generated per-frame)

## Technical Notes

- Font: inline 8×8 ASCII bitmap font defined as []uint8 bit patterns in
  pkg/overlay/font.go — covers digits, uppercase letters, colon, period,
  slash, space, % sign (everything needed for the debug strings)
- pkg/overlay (no build tag) — Metrics struct, Level type, CycleLevel(),
  Sampler (rolling FPS circular buffer), TextLayer.Render() → []byte (RGBA)
- pkg/overlay/draw.go (!headless) — composites TextLayer into
  pkg/framebuffer.Framebuffer (CPU path); draw_headless.go is a no-op stub
- pkg/overlay/gpu.go (!headless) — wgpu overlay texture + second render pass
  pipeline with SrcAlpha/OneMinusSrcAlpha blending (GPU path)
- F3 handler: glfw key callback in each backend's run loop; calls
  overlay.CycleLevel()
- Rolling FPS: circular buffer of last 60 frame durations; displayed as
  1 / (average duration)
