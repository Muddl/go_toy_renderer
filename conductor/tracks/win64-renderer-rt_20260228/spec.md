# Specification: Windows x64 Build for renderer-rt

**Track ID:** win64-renderer-rt_20260228
**Type:** Bug
**Created:** 2026-02-28
**Status:** Draft

## Summary

`renderer-rt` built on Windows produces a 32-bit (x86) executable that fails
to run on 64-bit Windows with "CreateProcess error=193, %1 is not a valid
Win32 application". The binary must target `GOARCH=amd64` on Windows so it
can load 64-bit GLFW/OpenGL DLLs and execute correctly on x64 systems.

## Context

Phase 9 added `cmd/renderer-rt` with GLFW + OpenGL via CGO (`window.go`,
build tag `!headless`). CGO delegates final linking to the local C toolchain;
if a 32-bit MinGW/GCC is first in `PATH`, the resulting PE is 32-bit. CI uses
`-tags=headless` (no CGO) but never pins `GOARCH=amd64` for Windows, leaving
both CI artifact architecture and local build architecture under-specified.

## Steps to Reproduce

1. Build `renderer-rt` on or for Windows without explicitly setting
   `GOARCH=amd64`.
2. Attempt to run the resulting `.exe` on a Windows x64 system with
   `--backend auto`.
3. Observe: `CreateProcess error=193, %1 is not a valid Win32 application`.

## Expected vs Actual Behaviour

- **Expected:** `renderer-rt.exe` launches and runs on Windows x64 systems.
- **Actual:** Process fails immediately with Win32 error 193 (wrong
  architecture / 32-bit binary attempting to load 64-bit DLLs).

## Acceptance Criteria

- [ ] CI Windows build job explicitly sets `GOARCH=amd64` for all
      `renderer-rt` build steps.
- [ ] Local build instructions in `CLAUDE.md` / `README` document the
      requirement for a 64-bit MinGW-w64 toolchain on Windows.
- [ ] CI artifact `renderer-rt.exe` (Windows) is a valid 64-bit PE executable
      (verifiable via `file renderer-rt.exe` or `dumpbin /headers`).
- [ ] `go env GOARCH` in the Windows CI job outputs `amd64`.

## Dependencies

Depends on existing CI config (`.github/workflows/ci.yml`) and
`cmd/renderer-rt` Phase 9 code.

## Out of Scope

- Supporting Windows 32-bit (x86) as a first-class build target.
- Changing the CGO / GLFW setup itself.
- Any GPU backend work (Phases 10+).

## Technical Notes

- `GOARCH=amd64` must be set as an env var on the Windows build step in CI,
  not just as a matrix value — Go picks up the env var at build time.
- For local builds with CGO (full windowed mode): 64-bit MinGW-w64 is
  required; the recommended install is via MSYS2 (`pacman -S
  mingw-w64-x86_64-gcc`).
- Headless CI builds (no CGO) should still pin `GOARCH=amd64` for
  consistency and to catch future CGO regressions early.
