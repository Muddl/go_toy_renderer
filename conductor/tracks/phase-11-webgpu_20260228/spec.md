# Specification: Phase 11 — WebGPU Integration via go-webgpu

**Track ID:** phase-11-webgpu_20260228
**Type:** Feature
**Created:** 2026-02-28
**Status:** Draft

## Summary

Implement WebGPU bindings using `github.com/go-webgpu/webgpu` v0.4.0 — a
Zero-CGo FFI Go package — wiring the existing `GPUBackend` stub in
`pkg/renderer` to a real wgpu Instance/Adapter/Device/Queue chain, and
rendering a Hello Triangle on the GPU via a hardcoded WGSL shader.

## Context

Phase 10 delivered `pkg/renderer`: a `Renderer` interface, `CPUBackend`
(GLFW + blit), and a `GPUBackend` stub whose `RenderFrame` returns "GPU not
yet implemented". Phase 11 makes the GPU backend real using
`go-webgpu/webgpu`, which differs from the originally-planned `wgpu-native`
CGo binding: it uses pure-Go FFI (no CGo compiler required) and loads
wgpu-native as a shared library at runtime via `WGPU_NATIVE_PATH`. `pkg/gpu`
is the designated package for all wgpu logic (per tech-stack dependency graph).

## User Story

As the developer, I want to initialise a WebGPU device via `go-webgpu/webgpu`
and render a Hello Triangle on the GPU so that I can verify the full wgpu
pipeline is functional before adding real geometry and shaders in later phases.

## Acceptance Criteria

- [ ] `github.com/go-webgpu/webgpu` v0.4.0 is in `go.mod` / `go.sum`
- [ ] `GPUBackend.Init()` calls `wgpu.Init()` then creates Instance → Adapter
      → Device → Queue → Surface (from GLFW window handle) without error on a
      machine with a GPU and `WGPU_NATIVE_PATH` set
- [ ] A Hello Triangle renders on the GPU at runtime (visible in the GLFW
      window) using a hardcoded WGSL shader
- [ ] `go run ./cmd/renderer-rt --backend gpu` runs without error and displays
      the triangle
- [ ] `pkg/gpu` achieves >80% test coverage; GPU integration tests gated by
      `GPU_TESTS=1` env var

## Dependencies

- **Runtime:** wgpu-native shared library reachable via `WGPU_NATIVE_PATH`.

  - macOS:   `assets/macos-aarch64/lib/libwgpu_native.dylib` (v27.0.4.0)

## Technical Notes

- Package: `github.com/go-webgpu/webgpu/wgpu` v0.4.0 — Zero-CGo FFI (no
  CGo compiler required for `pkg/gpu`; compiles on all platforms)
- Init chain: `wgpu.Init()` → `wgpu.CreateInstance(nil)` →
  `instance.RequestAdapter(nil)` → `adapter.RequestDevice(nil)` →
  `device.GetQueue()`
- Runtime: set `WGPU_NATIVE_PATH` to the platform shared library from committed
  assets — e.g. on Windows: `assets/windows-x86_64-gnu/lib/wgpu_native.dll`
- No build tags needed for `pkg/gpu`; GPU tests gated by `GPU_TESTS=1` at
  runtime; CI remains headless-only (no GPU on runners) but `pkg/gpu` must
  compile cleanly in the headless build and test matrix
- `.github/workflows/ci.yml` must be reviewed to confirm `pkg/gpu` is included
  in `-tags=headless` build/test steps without requiring `WGPU_NATIVE_PATH`
- `GPUBackend.Init()` returns a descriptive error if `wgpu.Init()` fails
  (library not found), enabling `--backend auto` CPU fallback
- Inline WGSL shader strings for Hello Triangle (no file I/O yet)
- v0.4.0 null handle guards are safe to pass nil descriptors where optional
