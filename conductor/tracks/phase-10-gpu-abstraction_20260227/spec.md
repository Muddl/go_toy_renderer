# Specification: Phase 10 — GPU Backend Abstraction

**Track ID:** phase-10-gpu-abstraction_20260227
**Type:** Feature
**Status:** Pending
**Created:** 2026-02-27

## Summary

Introduce a `pkg/renderer` package with a `Renderer` interface and two concrete backends — `CPURenderer` (wrapping Phase 9's CPU blit path) and a stub `GPURenderer` — so that backend selection is decoupled from the main loop.

## Context

Phase 10 creates the architectural seam that lets Phases 11–16 swap in GPU rendering without touching the application loop. The `Renderer` interface is intentionally minimal; it grows in subsequent phases. The CPU backend must still produce identical output to the Phase 9 path.

**Source docs:** `14-gpu-backend.md`

## User Story

As a developer, I want a `Renderer` interface so that I can swap between CPU and GPU backends at startup without changing the rendering loop.

## Acceptance Criteria

- [ ] `pkg/renderer` package defines `Renderer` interface: `Init(width, height int) error`, `RenderFrame(scene *render.Scene) error`, `Shutdown()`
- [ ] `CPUBackend` implements `Renderer` — runs `pkg/render.Render()` + GLFW blit (extracted from Phase 9)
- [ ] `GPUBackend` stub implements `Renderer` — `Init` returns `nil` (ready for Phase 11 wgpu code), `RenderFrame` returns `errors.New("GPU not yet implemented")`
- [ ] `cmd/renderer-rt` uses `renderer.New(backendFlag)` factory to instantiate backend
- [ ] `--backend auto` selects GPU backend, falls back to CPU on error
- [ ] Unit tests for `CPUBackend` and `GPUBackend.Init`, factory selection
- [ ] All existing tests still pass: `go test ./...`

## Dependencies

- `pkg/render` — CPU render pipeline
- Phase 9 windowing infrastructure

## Out of Scope

- Actual GPU rendering code (Phase 11)
- Any wgpu-native CGo bindings (Phase 11)

## Technical Notes

- `Renderer` interface lives in `pkg/renderer/renderer.go`; backends in `pkg/renderer/cpu.go` and `pkg/renderer/gpu.go`
- Keep the interface minimal — resist adding methods that only one backend needs
- The factory `New(backend string) (Renderer, error)` pattern avoids import cycles
