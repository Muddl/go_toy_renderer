# Specification: Phase 11 — WebGPU Integration

**Track ID:** phase-11-webgpu_20260227
**Type:** Feature
**Status:** Pending
**Created:** 2026-02-27

## Summary

Integrate wgpu-native via CGo into the `GPUBackend` to create a real WebGPU device, swapchain, and render pass. The acceptance milestone is a "hello triangle" rendered via the GPU pipeline visible in the GLFW window.

## Context

Phase 11 is the first phase where pixels are produced by the GPU. wgpu-native provides a Rust-based WebGPU implementation that exposes a C API for CGo consumption. The backend targets D3D12 on Windows, Metal on macOS, and Vulkan on Linux. The hello triangle uses a hardcoded WGSL shader; HLSL compilation is introduced in Phase 13.

**Source docs:** `14-gpu-backend.md`

## User Story

As a developer, I want the GPU backend to open a wgpu-native WebGPU device and render a coloured triangle so I can verify the GPU pipeline end-to-end before adding geometry complexity.

## Acceptance Criteria

- [ ] `pkg/gpu` package wraps wgpu-native C API via CGo (`wgpu.h` / pre-built `.dll`/`.dylib`/`.so`)
- [ ] `GPUBackend.Init` creates: `wgpu.Instance` → `wgpu.Surface` (from GLFW window) → `wgpu.Adapter` → `wgpu.Device` → `wgpu.SwapChain`
- [ ] `GPUBackend.RenderFrame` acquires swapchain texture → begins render pass → draws hello triangle → presents
- [ ] Hello triangle uses inline WGSL (hardcoded string); no HLSL yet
- [ ] `--backend gpu` shows a coloured triangle in the GLFW window at 60 fps
- [ ] `--backend cpu` still works unchanged
- [ ] Build instructions in `README.md` for acquiring wgpu-native pre-built binaries
- [ ] `pkg/gpu` has integration tests gated behind `//go:build gpu` build tag

## Dependencies

- wgpu-native pre-built binaries (platform-specific; not in `go.mod`)
- `pkg/renderer` interface (Phase 10)
- GLFW window handle passed to wgpu surface creation (Phase 9)

## Out of Scope

- HLSL shader compilation (Phase 13)
- Rendering actual scene geometry (Phase 12)
- Multiple render pipelines or shader variants

## Technical Notes

- wgpu-native CGo wrapping: `#cgo LDFLAGS: -lwgpu_native` or similar
- On Windows: requires `wgpu_native.dll` in PATH or alongside binary
- Adapter request is async in WebGPU spec; wgpu-native provides synchronous wrapper
- Swapchain format should query `surface.GetPreferredFormat(adapter)` rather than hardcoding BGRA8
