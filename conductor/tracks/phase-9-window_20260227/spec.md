# Specification: Phase 9 — Window & Real-time Display

**Track ID:** phase-9-window_20260227
**Type:** Feature
**Status:** Pending
**Created:** 2026-02-27

## Summary

Add a real-time windowed renderer (`cmd/renderer-rt`) using GLFW for windowing and an event loop that blits the CPU framebuffer to the screen at ~60 fps, making the existing CPU renderer interactive.

## Context

Phase 9 is the bridge from the batch PNG renderer to real-time display. It introduces GLFW windowing, an event loop, and CPU→GPU image blit without yet introducing a GPU rendering pipeline. The existing `pkg/render` CPU renderer is reused unchanged; we just display its output in a window every frame. This sets up the windowing infrastructure needed by all subsequent GPU phases.

**Source docs:** `16-realtime-display.md`

## User Story

As a developer learning GPU graphics, I want to see the 3D scene rendered in a real-time window so that I can interactively observe rendering changes and prepare for GPU acceleration.

## Acceptance Criteria

- [ ] New binary `cmd/renderer-rt` opens a GLFW window (default 1280×720, configurable)
- [ ] Event loop runs at ~60 fps (frame timing via `time.Sleep` or GLFW `SwapInterval`)
- [ ] Each frame: run CPU `pkg/render.Render()` into framebuffer → convert float pixels to RGBA bytes → upload to OpenGL texture → blit fullscreen quad
- [ ] ESC or window close exits cleanly (no goroutine leaks)
- [ ] `--backend` flag: `cpu` (default), `auto`, `gpu` (gpu = error "not yet implemented" in Phase 9)
- [ ] Width/height configurable via `--width` / `--height` flags
- [ ] `go test ./cmd/renderer-rt/...` — at minimum: flag parsing test, framebuffer→bytes conversion test
- [ ] All existing tests still pass: `go test ./...`

## Dependencies

- `github.com/go-gl/glfw/v3.3/glfw` — windowing and OpenGL context creation
- `github.com/go-gl/gl/v4.1-core/gl` — OpenGL bindings for texture blit
- `pkg/render` — existing CPU renderer (no changes)

## Out of Scope

- GPU rendering (Phase 11)
- wgpu-native (Phase 11)
- Input handling beyond close/ESC (later phases)
- Resizable window (can be fixed size for now)

## Technical Notes

- GLFW requires the main goroutine; call `runtime.LockOSThread()` at top of `main`.
- Use `go.sum` and `go mod tidy` after adding GLFW deps.
- The OpenGL texture blit is temporary scaffolding; it will be replaced by wgpu-native swapchain in Phase 11.
- Build tag `//go:build !headless` allows CI to skip GLFW tests on headless runners.
