# Specification: CI Pipeline Hardening

**Track ID:** ci-hardening_20260228
**Type:** Chore
**Created:** 2026-02-28
**Status:** Draft

## Summary

Full review and hardening of the CI pipeline (`ci.yml` and `security.yml`) to eliminate flaky failures caused by the Windows/CGo windowing change and fragile tooling pins in the security workflow. Goal: a consistently green baseline before Phase 10 starts.

## Context

Phase 9 introduced CGo (GLFW + OpenGL) for `cmd/renderer-rt`. This made Windows builds sensitive to toolchain architecture and the race detector. Separately, `security.yml` uses `securego/gosec@master` (unpinned) and silences the entire license check with `|| true`, meaning it can fail or silently pass without surfacing real issues.

## Specific Problems Found

### `ci.yml`

| # | Location | Problem | Impact |
|---|----------|---------|--------|
| 1 | `test` job, all OS | `go test -race` runs on `windows-latest` — race detector DLL fails with CGo on Windows | Intermittent Windows test failures |
| 2 | `format-validate`, `lint`, `test`, `security` jobs | Go version `1.25` specified — Go 1.25 does not yet exist; `setup-go` behaviour with a nonexistent version is unpredictable | Possible silent version substitution or outright failure |
| 3 | `lint` job, `golangci-lint-action` | `version: latest` — lint binary version floats on every run | Unexpected new linter errors on any golangci-lint release |
| 4 | `security` job | `govulncheck@latest` installed at runtime — version floats | Behaviour changes without code change |

### `security.yml`

| # | Location | Problem | Impact |
|---|----------|---------|--------|
| 5 | `gosec-scan` job | `securego/gosec@master` — any breaking commit on gosec master immediately breaks the scan | Unpredictable scan failures/breakage |
| 6 | `license-check` job | `go-licenses report ... \|\| true` and `go-licenses save ... \|\| true` — entire job is suppressed | License violations never surface in CI |
| 7 | All jobs | `govulncheck@latest` installed at runtime | Same as issue 4 |
| 8 | All jobs | Go version `1.24` — inconsistent with `ci.yml`'s `1.25` | Different tool behaviour between pipelines |

## Acceptance Criteria

- [ ] `go test -race` is skipped on `windows-latest`; Windows tests run without the race flag
- [ ] Go version references are consistent and pinned to an existing stable release (`1.24`) across both workflows
- [ ] `golangci-lint-action` specifies a pinned linter binary version (not `latest`)
- [ ] `govulncheck` is installed at a pinned version in both `ci.yml` and `security.yml`
- [ ] `securego/gosec` is pinned to a specific release tag (not `@master`)
- [ ] `|| true` is removed from `go-licenses` steps — license violations fail CI
- [ ] All fragile patterns are documented in `conductor/ci-fragility.md` for future phases
- [ ] CI passes cleanly on Linux, macOS, and Windows after all changes
- [ ] `-tags=headless` path is untouched and remains working for all non-CGo steps

## Dependencies

Depends on existing `.github/workflows/ci.yml` and `.github/workflows/security.yml`. No incomplete tracks required.

## Out of Scope

- Adding new CI jobs (Codecov, coverage badges, deployment)
- Changing coverage thresholds
- Restructuring the overall pipeline shape or job graph
- macOS/Linux-specific changes not related to the identified fragile patterns

## Technical Notes

- The race detector issue on Windows is a known CGo/DLL limitation — the fix is a conditional step (`if: matrix.os != 'windows-latest'`), not removal of race coverage overall
- `golangci-lint-action@v8` is the action major version (acceptable semver pin); `version: latest` inside the `with:` block is the linter binary version (fragile — pin to e.g. `v2.1.6`)
- `go-licenses` with `|| true` should have the suppression removed; if a step fails due to missing dependencies it should be investigated, not silenced
- govulncheck pinned version: use `golang.org/x/vuln/cmd/govulncheck@v1.1.3` (latest stable as of 2026-02)
